# Golden corpus

Recorded and synthetic terminal output streams, each replayed into every terminal engine of the build
(alacritty today, libghostty-vt behind the `ghostty` cargo feature) and compared **cell by cell** with
reviewed expectations. PLAN.md §5 Phase 0 and §10: engine updates are one reviewed change together with
this corpus.

## Layout

```
corpus/<name>/stream.vtrec              the output stream (read-chunk boundaries and timing kept)
corpus/<name>/meta.json                 description, source, cols, rows, tags, command, env, recorded_on/at, notes
corpus/<name>/input.script              the scripted input of a recording (optional)
corpus/<name>/expected.<engine>.json    the screens the engine produced, reviewed and blessed
corpus/<name>/reviewed-differences.md   accepted differences between engines (once a second engine exists)
```

`source` is `recorded` (the ConPTY recorder), `session` (a live terminal of the service) or `synthetic`
(generated by `crates/canvas-corpus/src/synth.rs`; a test keeps the stored streams equal to the generator).

## `.vtrec` format (version 1)

JSON lines, UTF-8. The first line is the header, every further line one event:

```
{"vtrec":1,"cols":120,"rows":40,"program":"powershell.exe -NoLogo","description":"…","source":"conpty","recorded_at":"2026-10-27T10:00:00.000Z"}
{"t":12,"s":"\u001b[?25lPS C:\\> "}   one read of output whose bytes are valid UTF-8 (JSON-escaped)
{"t":3,"x":"e4b8"}                     one read of output as lowercase hex (reads that split UTF-8 or carry invalid bytes)
{"t":0,"resize":[100,30]}              the terminal was resized to cols x rows
{"t":500,"in":"dir\r"}                 input the recorder typed ("inx": hex); documentation only, never replayed
{"t":0,"mark":"listing"}               checkpoint: the expected file keeps the screen at this point
```

* `t` is milliseconds since the previous line (for the first event: since the program started).
* Each output line is exactly one `read()` of the PTY, so replays feed the same chunk boundaries.
* A later header line starts a new segment (the service tap appends when a terminal id is reused);
  readers use the last segment. A truncated last line (a tap mid-write) is ignored.
* Unknown event keys are skipped, so newer writers stay readable.

## Expected files

`expected.<engine>.json` is pretty JSON with a stable field order and one row per line:

* `engine`; `events`: title changes and the final title, bells, OSC 52 clipboard writes, OSC 9;4 progress
  states, notifications (OSC 777) and the replies the engine sent to the program's queries;
* `screens`: one per `mark` in stream order, then `end`. Each has `cols`, `rows`, `cursor` (`null` when hidden),
  `cursor_shape` (0 block, 1 underline, 2 bar, 3 hollow), `cursor_blink`, `display_offset`, `history`
  (scrollback lines), `modes` (`MODE_*` bits; `mode_names` spells them out), `links` (OSC 8 targets),
  `text` (plain rows for reading) and `lines` (protocol-8 `Run8` rows: text, grapheme clusters, width,
  colours, flags, underline colour, link; a soft-wrapped row ends with an empty marker run with flag
  `F8_SOFTWRAP` = 4096 whose `col` is where the row's text ends).

`text` and `mode_names` are derived for reviewers and not compared. Everything else is: cells are
compared on a full cols x rows grid (blank default cells and trailing-blank trimming are equivalent, links
by target URL), plus each row's soft-wrap state, cursor, shape, blink, modes, history, display offset and
the events. `corpus show` marks soft-wrapped rows with `↩`.

Replay uses the hosted terminal's configuration (scrollback 5000, kitty keyboard answered), applies resizes
in stream order and flushes a synchronized update (DEC 2026) that is still open 150 ms of stream time later
or at the end of the stream, as the host does.

## Commands

```
copilot-canvas corpus list                               entries, sizes, marks, expected engines, tags
copilot-canvas corpus check [--engine NAME] [NAME…]       replay + compare; non-zero exit on any difference
copilot-canvas corpus bless [--engine NAME] [NAME…]       (re)write expected files; prints what changed
copilot-canvas corpus synth [NAME…]                      regenerate the synthetic streams (then bless)
copilot-canvas corpus show NAME [--engine NAME] [--mark M] print the replayed screens and events
copilot-canvas corpus diff [NAME…] [--engine A] [--against B]
                                                         compare two engines' expected files (default alacritty vs ghostty)
```

The corpus folder is `--corpus DIR`, else `COPILOT_CANVAS_CORPUS`, else `./corpus`, else the repository's.
`cargo test --workspace` runs the same check for every entry and every engine in the build
(`crates/canvas-corpus/tests/golden.rs`), plus a deterministic, time-bounded robustness test that feeds
mutated and re-chunked corpus streams, random resizes, scrolls and input encodings to each engine.

### Recording a program

```
copilot-canvas record --entry NAME [--cols 120] [--rows 40] [--input SCRIPT] [--seconds 30]
                      [--env NAME=value]… [--cwd DIR] [--description TEXT] [--tags a,b] [--notes TEXT]
                      -- PROGRAM [ARGS…]
copilot-canvas record --out FILE.vtrec … -- PROGRAM [ARGS…]      (a file outside the corpus)
```

The program runs in a ConPTY of the given size with `TERM=xterm-256color` and `COLORTERM=truecolor`, like
hosted terminals. Output is fed to an alacritty emulator whose replies (cursor position, colours, device
attributes, kitty keyboard) are written back, because ConPTY and TUIs wait for them. Recording ends when the
program exits (the pseudoconsole is drained and closed) or after `--seconds` (the process tree is killed).

Input scripts (`#` comments):

```
wait 500              sleep (ms)
wait-for PS C:\       until the screen shows the text (timeout: `timeout MS`, default 15000)
wait-quiet 300        until no output arrived for 300 ms since the step started (bounded by the timeout)
timeout 20000         timeout of later wait-for / wait-quiet steps
type dir\r            raw text; escapes \r \n \t \e \\ \xNN
line dir              text, then Enter
key enter             enter tab backtab backspace esc up down left right home end pgup pgdn insert delete
                      space f1..f12 or one character, with ctrl- alt- shift- prefixes (key ctrl-c)
paste text            bracketed paste when the program enabled it
resize 100 30         resize the pseudoconsole (recorded as a resize event)
mark NAME             checkpoint kept in the expected files (use before quitting full-screen programs)
kill                  end the program now
```

### Recording a live session (`record --session`)

The terminal service records nothing by default. With `COPILOT_CANVAS_RECORD=<dir>` in its environment, every
terminal's PTY reader appends its raw reads to `<dir>/<terminal-id>.vtrec` (hex chunks, header on the first
read, resize events when the size changed; I/O errors silently stop the tap). Then:

```
$env:COPILOT_CANVAS_RECORD = "$HOME\.copilot-canvas\recordings"
copilot-canvas service stop            # ends the running sessions
copilot-canvas                         # reopen: the service restarts with recording on; use the session
copilot-canvas record --session ID --entry copilot-NAME --description "…" --tags copilot,…
```

`ID` is the terminal id (a unique prefix is enough). The folder is `--dir`, else `COPILOT_CANVAS_RECORD` of the
current shell, else `<home>\recordings`. The command keeps the last run of that terminal, re-encodes readable
chunks as text and prints the final screen. Without a recording it prints these instructions.

## Adding an entry

1. Record (`record --entry`) or add a generator to `synth.rs` and run `corpus synth NAME`.
2. Check the stream for secrets and personal data (account names, e-mail addresses, tokens); recordings keep
   everything the program printed, including paths and process lists.
3. `corpus bless NAME`, then read `expected.alacritty.json` (`text` rows, events, modes) or `corpus show NAME`
   and confirm the screens are what a correct terminal shows.
4. Commit stream, meta, script and expected files together.

## Review policy

* An expected file changes only in a reviewed commit that says why: an engine update, an adapter fix or a new
  recording. `corpus bless` prints the differences to the previous expectation; paste the relevant part into
  the commit message.
* Engine updates (alacritty_terminal or libghostty-vt versions, adapter changes) land in the same change as the
  re-blessed corpus, so the diff of `expected.*.json` is the review of the engine change.
* A second engine gets its own `expected.<engine>.json`. Where it legitimately differs from another engine
  (grapheme clustering, reflow, query replies), record the accepted difference in
  `<name>/reviewed-differences.md` (`corpus diff NAME` lists them) instead of bending one engine to the other.
* When a build adds an engine, `corpus check` and the test fail with `MISS` until its expected files are blessed
  and reviewed.

## Known issues

* **alacritty: scrolled view + scroll region overflows the history.** alacritty_terminal 0.26 `Grid::scroll_up`
  raises `display_offset` whenever the content scrolls while the view is scrolled back, also for a scroll region
  that does not start at the top, where no line enters the history. The adapter's `snapshot()` then indexes past
  the scrollback: a debug assertion (`storage.rs:225`), stale rows in release, and an out-of-bounds panic once the
  offset outgrows the allocated rows. Reachable in the service when a user has scrolled back and the program
  scrolls a region on the primary screen. Fix in the adapter: clamp the offset to `history_size()` after feeding
  (or when snapshotting). Regression test: `scrolled_view_survives_output_in_a_scroll_region` (passes).
  **Fixed:** `AlacrittyEmulator::clamp_offset` runs after every feed; the robustness test now also feeds output
  while the view is scrolled back.

| `powershell` | recorded | PowerShell 5.1: prompt, `dir` listing, `Get-Process` table, coloured `Write-Host`, a resize |

| `vim` | recorded | vim (Git for Windows): alternate screen, inserted Unicode lines, `:set number`, `:q!` |
| `opencode-startup` | recorded | OpenCode 1.19.4 start-up screen (no prompt sent), quit with Ctrl+C |
| `claude-startup` | recorded | Claude Code start-up (folder-trust prompt; no prompt sent), quit with Esc |
| `synth-*` | synthetic | Unicode/emoji/ZWJ/CJK/wrap, SGR matrix, OSC 8/52/9;4/777/titles/bell, screen operations, modes and cursor shapes, synchronized updates, resize reflow, one-byte reads |

**Gap: real GitHub Copilot CLI sessions** (prompts, tool output, diffs, tab bar, mouse mode, permission
prompt) are not in the corpus yet: Copilot CLI is not installed on the machine that recorded it. Record them
on a machine with Copilot via the service tap (`record --session`, above) so the stream is exactly what a
hosted terminal received, e.g. `copilot-prompt`, `copilot-tool-output`, `copilot-diff`, `copilot-permission`,
`copilot-mouse`; add `mark` checkpoints by recording short sessions that end on the screen of interest.
