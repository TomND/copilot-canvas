Atelier - remote setup (agents on the Cloud PC, canvas at home)
=======================================================================

Both programs are self-contained (no Visual C++ runtime, no Rust needed).
Put the SAME build on both machines: older clients cannot pair with it.

1. Install on both PCs
   Unzip into a folder of your choice, e.g. C:\Tools\Atelier, and add
   that folder to your PATH (or call the .exe with its full path).
   Run `atelier doctor` to check what was found.

2. Cloud PC (where the agents run)
   atelier remote tunnel-setup                 (writes the tunnel automation; remote.listen = 127.0.0.1:47600)
   devtunnel user login -g                            (once; GitHub sign-in)
   devtunnel create atelier
   devtunnel port create atelier -p 47600
   devtunnel show atelier                      (port 47600 listed; no anonymous access)
   atelier automations apply Atelier-Tunnel --yes
   atelier automations run Atelier-Tunnel
   atelier service stop                        (then start it so it listens on 127.0.0.1:47600)
   atelier service start
   atelier remote pair --name home-pc          (prints a code XXXX-XXXX-XXXX, valid 10 minutes)
   atelier doctor                              (listening, devtunnel signed in, tunnel task running)

   If `devtunnel` is not on PATH, `remote tunnel-setup` prints its full path.

3. Home PC
   winget install Microsoft.devtunnel
   devtunnel user login -g                            (the SAME account as on the Cloud PC)
   atelier remote add cloudpc --tunnel atelier --port 47600 --code XXXX-XXXX-XXXX
   atelier --remote cloudpc                    (terminal UI)
   atelier --gui --remote cloudpc              (GPU client)

   Optional: `--vscode-tunnel NAME` on `remote add` opens Cloud PC files in
   VS Code through that VS Code tunnel; otherwise they open in a read-only viewer.

4. Everyday use
   - The canvas reconnects by itself after network drops ("Offline,
     reconnecting..."); typing is blocked while offline, never queued.
   - Sessions keep running on the Cloud PC when the home client closes.
   - atelier remote clients / remote revoke NAME   (Cloud PC)
   - atelier remote servers / remote forget NAME   (home)

If something fails: `atelier doctor` and the service log
(%USERPROFILE%\.atelier\service-default.log) on the Cloud PC;
`devtunnel user show` at home should say "Logged in as ... using GitHub".
More: docs/REMOTE.md in the repository.
